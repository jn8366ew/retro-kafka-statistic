# 실험 결과

[README](../README.md) 의 상세판. 판정은 로그가 아니라 원천 DB 에서 독립 계산한 기대값과 실제 집계를 대조해서 한다.

공통 입력: 행사 2개(GALA-01, EXPO-02) × 예약 6개 = 고정 12건. 파티션 2, 키 = 예약 ID.
기대 집계는 GALA-01 = 20500 / 2건, EXPO-02 = 61000 / 2건.

## C1 — 키·파티션·오프셋

- murmur2 예측 = 실제 파티션 **12/12 일치**. crc32(librdkafka 기본) 예측은 4건이 달랐다 — 파티셔너를 명시하지 않으면 언어 간 배치가 달라진다.
- 같은 행사 EXPO-02 가 p0·p1 로 갈라졌다. 키가 예약 ID 라 **행사는 파티션을 정하지 않는다** (C2·C4 문제의 전제).
- `--dup`: 같은 event_id 가 offset 10, 11 로 두 건 저장. `enable.idempotence` 는 전송 재시도 중복만 막는다.
- 발행 분포 = watermark = 커밋 위치 (p0 10 / p1 2) 삼자 일치.

## C2 — 수동 커밋과 전달 보장

| 실험 | 조건 | 결과 |
| --- | --- | --- |
| E1 정상 | 기본 | 집계 OK, 처리 각 1회, 커밋 = 끝 |
| E2 At-least-once | DB 반영 후 커밋 전 크래시 → 재기동 | 12건 재처리, **집계 OK** |
| E3 At-most-once | 커밋 후 DB 반영 전 크래시 → 재기동 | **12건 누락, lag 0**. 후속 이벤트가 온 행사만 우연히 복구 |
| E4 배치 일부 | 배치 중간 크래시 | 한 행사만 반영·미커밋 → 재기동 후 OK |
| E5 잘못된 계속 | 실패 무시하고 커밋 | 실패 구간을 넘어 커밋, **영구 누락** |
| E5 올바른 정지 | 실패 시 커밋 없이 정지 | 원인 제거 후 재기동하면 OK. 대신 무관한 행사도 함께 멈춤 (→ C3 동기) |
| E6 커밋 실패 | 처리 지연 > `max.poll.interval.ms` | 그룹 이탈 → 커밋 `UNKNOWN_MEMBER_ID` → 재할당 후 재처리 → OK. **이미 커밋된 DB 쓰기는 취소되지 않는다** |
| E7 커밋 방식 | 인자 없는 sync / async | async 커밋 실패는 호출 지점이 아니라 **콜백에서만** 보인다 |
| E8 리밸런스 | 워커 2개 중 하나 크래시 | ~11초 후 재배정, 미커밋 구간만 재처리 |

집계가 틀린 것은 E3·E5(잘못된 계속) 두 번이고 둘 다 **누락**이었다. 중복 누적은 한 번도 없었다.

## C4 — stale write 와 행사별 잠금

| 실험 | 조건 | 결과 |
| --- | --- | --- |
| s1 | 잠금 없음 | 늦게 끝난 트랜잭션이 옛 값으로 덮음 (STALE) |
| s2 | 행사별 잠금이 첫 조회 | 뒤 트랜잭션이 대기 후 최신값 (OK) |
| s3 | 잠금 전에 먼저 조회 | 잠금은 기다렸지만 **옛 스냅샷으로 덮음** (STALE) |
| s3b | s3 + READ COMMITTED | 잠금 후 조회가 최신 커밋을 봄 (OK) |
| K1 | 워커 2개, 잠금 없음 | stale write. 누락 0, 재처리 0, lag 0 인데 집계 MISMATCH |
| K2 | K1 + `--lock` | 한쪽이 ~5초 대기 후 최신값 (OK) |
| K3 | K2 + 잠금 대기 타임아웃 3초 | 타임아웃 → 커밋 없이 정지 → 재기동 후 OK. 틀린 값이 아니라 늦은 값 |
| R1 | 컨슈머만 잠금, 복구 배치는 잠금 없음 | 복구 배치가 옛 값으로 덮음 |
| R1b | 복구 배치도 잠금 | OK — **모든 쓰기 경로가 같은 규칙을 지켜야 한다** |

- 잠금은 최신값이 아니라 **순서**를 보장한다. 결과가 맞는 이유는 원천 변경마다 이벤트가 오고 뒤 작업이 잠금 후 다시 읽기 때문이다.
- 함정: 발행기의 `INSERT IGNORE INTO event_lock` 이 이미 있는 행에 공유 잠금을 요청해, 집계 잠금이 원천 쓰기를 막았다.
  잠금 없는 SELECT 로 존재를 먼저 확인하도록 고쳤다.
- 비용: 같은 행사로 몰리는 부하에서는 행사 단위 직렬화가 처리량 상한이 되고, 잠금 중 DB 연결을 쥐고 있다.
